## 本轮修复

1. 修复模型返回异常 Unicode 字符串时的入库崩溃：
   JSON 中的孤立代理字符可以被解析，但不能编码成 SQLite 所需的 UTF-8。
   现在 AI 层在返回前验证编码，异常时使用通用回应；如果已解析出 crisis，
   则保留危机等级并使用安全预设回应。两个专项回归测试均通过。
2. 更新仍停留在第一阶段的 README，补齐 DeepSeek、管理员、回复、
   reaction、预警和示例脚本的运行步骤，避免按过时说明准备现场演示。

## 尚未验证与原型限制

- 当前启动环境未配置 `ADMIN_PASS`、`DEEPSEEK_API_KEY`。
  管理员登录流程已通过模拟环境测试；现场服务须设置密码后重启。
- 没有使用真实 DeepSeek Key 发起联网请求，不消耗 API 额度。
  模拟测试不能证明真实网络、Key、余额或模型可用；上台前需单独试跑。
- 关键词与拼音兜底不能保证识别全部风险，也可能误判；AI 不是诊断工具。
- reaction 统计点击次数，不统计独立人数，没有跨会话防刷。
- 没有实时通知、值守或专业危机干预，危机队列不等于报警服务。
- 管理员只有共享密码，没有完整账号、审计记录或全局登录限流。
- 数据库明文保存用户输入；匿名界面、隐私提示和页脚声明不能自动消除
  文本里的个人信息。仅使用虚构数据，不向真实未成年人开放收集。
- 发帖与回复正文会发送给 DeepSeek，应在真实部署前另行设计知情同意、
  数据保留与删除机制。
- 求助资源沿用项目发起人提供的原文，未核实号码和可用性。
- 本轮没有进行浏览器截图级视觉验收；界面流程由 Streamlit AppTest 验证。
