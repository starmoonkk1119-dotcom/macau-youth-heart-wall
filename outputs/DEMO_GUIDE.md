# 心声墙：3 分钟现场演示

## 上台前

1. 在项目目录激活虚拟环境，设置 `ADMIN_PASS` 和 `DEEPSEEK_API_KEY`。
   变量须在启动 Streamlit 的同一终端设置，修改后重启服务。
2. 首次执行 `python outputs/seed.py`。重复彩排时可使用
   `python outputs/seed.py --reset-demo` 恢复种子示例的初始状态。
   此选项仅重建这七条示例及其回复、reaction，不会清空其他帖子。
   若曾从网页另外提交测试帖，那些帖子仍会保留。
3. 启动 `python -m streamlit run outputs/app.py --server.address 127.0.0.1`，
   打开终端实际显示的地址。不要同时用多个服务混淆环境变量。
4. 用虚构文本试跑一次 AI，确认 Key、余额、网络和指定模型可用。
   不把这次联网试跑与自动化的模拟 API 测试混为一谈。
5. 确认墙上能找到“DEMO 示例 07”，它的四个关怀次数应从 0 开始。
   管理员队列应有示例 06（强度 5、crisis）及示例 04、05。
6. 准备好管理员密码，不在投屏终端显示实际密钥，不让观众输入真实经历。
7. 演示前自行核实求助资源号码；本项目没有验证其可用性。

说明：种子数据的回应已明确标成“DEMO 预设回应”，不是现场模型生成结果。
若未设置 API Key，网站仍可演示人工审核和 reaction，但必须说明
新增发帖显示的是异常兜底回应，不要把它称为实时 AI 结果。

## 现场操作顺序

| 时间 | 操作 | 一句话讲解 |
| --- | --- | --- |
| 0:00–0:20 | 打开心声墙，展示带 DEMO 标签的帖子、已通过回复和页脚。 | “所有内容都是虚构示例；这是本地黑客松原型，不是真实求助服务。” |
| 0:20–1:00 | 去“写心声”，输入下方虚构文本，勾选公开并提交，展示回应和待人工审核状态。 | “一次模型请求返回分类、强度、陪伴回应和审核判断；AI 说 safe 也不能直接公开。” |
| 1:00–1:35 | 去“管理员”登录，先指出顶部红色示例 06。通过示例 04，再通过其下标为“示例回复 02”的回复，切回墙确认二者出现。 | “AI 是初筛，公开前仍由人工把关；回复也有独立审核。” |
| 1:35–2:10 | 找到示例 07，点击一次“抱抱”，再连续点击三次“我有点担心你”。展示计数、帖子退出公开墙和求助框。 | “担心达到阈值会升级到人工安全队列，不再继续公开扩散。” |
| 2:10–2:40 | 回到管理员，查看示例 07 已进入 crisis 队列，与强度 5 的示例 06 一起排在普通待审核内容前面。保留危机帖，不为了演示强行通过。 | “既支持模型强度预警，也支持关怀互动触发预警；这里没有实时报警通知。” |
| 2:40–3:00 | 展示示例 05 的“未同意公开”标记；有余裕就通过它并确认不出现在墙上，最后回到页脚收尾。 | “公开同意与审核通过是两个条件；我们先验证陪伴与人工把关流程，而不是替代专业帮助。” |

发帖文本（仅为虚构演示）：

```text
[DEMO 现场示例 | 虚构、非真实个人数据]
最近温习有点紧张，怕小组讨论时说错话，希望得到一点鼓励。
```

## 现场卡顿时

- AI 等待超过约 15 秒，不要反复点击提交；可先口头说明，再切换到
  已预置的审核流程。此时可能尚未入库，不要宣称已经保存成功。
- 模型调用设置了超时并关闭自动重试；若最终失败，会保存通用回应并转人工。
  这不是总耗时严格为 30 秒的保证。
- 不要在 3 分钟主线中再做第二次联网回复；现成的待审核示例回复已能验证流程。
- 管理员入口关闭时，说明是未设置 `ADMIN_PASS`，下台后设置并重启；
  不要临时移除密码检查。
- 若示例 07 已不在墙上，可能上次彩排已经升级；演示前重置示例，而非现场改 SQL。
- 界面按内容里的“示例 04/06/07”标签寻找，不依赖数据库 ID。

## 演示边界

reaction 计的是点击次数，不是独立人数；当前没有跨会话防刷。
页脚按要求声明只使用示例，但系统仍会保存输入，不能自动保证没有真实个人信息。
不对外开放给真实未成年人试用，不公布数据库，不承诺实时值守或热线可用性。
