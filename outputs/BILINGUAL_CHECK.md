## 危机检查的准确含义

自动化测试确实切换到 English，然后提交中/英文虚构危机文本，
通过真实 OpenAI SDK 的模拟 HTTP 传输接收 `moderation="crisis"`。
应用将其保存为 `crisis`，不公开，并显示英文求助资源。
模型已解析的 crisis 在其他字段校验失败时仍被保留，兜底回应也使用英文。
无效 JSON、缺 Key、网络错误仍使用 `need_review`，不会自动通过。
拼音命中仍只将 safe 至少升级到 need_review，不擅自改变原有判定逻辑。

隔离运行时的模拟服务固定返回 crisis，只用于确认 UI 到数据库的处理链路，
不构成真实模型识别能力测试。当前环境没有真实 DeepSeek Key，
因此没有发送真实服务请求，也没有验证真实模型对某条英文文本的语义判定。
在有 Key 的演示终端中，仍需用虚构文本做一次真实服务联调。

## 手工联调

1. 在启动 Streamlit 的终端设置 `DEEPSEEK_API_KEY` 和 `ADMIN_PASS` 后重启服务。
2. 切换 English，提交明确标为 DEMO 的虚构英文危机文本，不加入真实个人信息。
3. 确认看到英文陪伴回应与求助框；管理员登录后确认该帖在 crisis 队列中。
4. 用一条中文虚构普通内容在英文界面发帖，确认正文仍中文、AI 回应英文、
   状态 pending，且不会自动出现在公开墙。
5. 模型与网络有不确定性；若回退为 need_review，应查看不含正文或密钥的错误类型，
   不要把模拟测试结果当作真实服务保证，也不要为演示降低危机审核要求。

热线号码与资源文字按项目发起人提供的信息保留，号码及可用性仍需其自行核对。
