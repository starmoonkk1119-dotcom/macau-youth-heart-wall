# Macau Youth Heart Wall

Macau Youth Heart Wall is an anonymous, bilingual space where young people in Macao can share a feeling, receive an immediate supportive response, and be met with human review before anything becomes public.

- **Live demo:** [macau-youth-heart-wall.streamlit.app](https://macau-youth-heart-wall-dzorh4dwekxzu28y7x4wtv.streamlit.app/)
- **Event:** DSH Hacks V2, theme: AI x Healthcare
- **Developer:** LinXinYue

> **Disclaimer:** This is a hackathon prototype. It is not a medical device and is not a substitute for professional help or emergency services.

## The Problem

Many young people carry academic, family, social, and emotional pressure without an easy first place to express it. The project uses the following public research and media context to explain why a low-friction, supportive space may matter:

- A 2020 *Scientific Reports* study reported a depression screening result of approximately **35.2%** among a specific sample of university students in Macao.
- An academic study reported that approximately **22%** of surveyed Macao adolescents fell into a severe-to-extremely-severe anxiety symptom group.
- A 2026 local media reference described youth mental-health pressure in Macao as an **"invisible pandemic."** The original article citation should be verified before this wording is treated as a confirmed media quotation.

These figures come from different studies, samples, definitions, and time periods. They should not be read as a current prevalence estimate for every young person in Macao, and they are not measurements generated by this platform.

## Key Features

- **Anonymous posting:** Users can write a feeling without creating a public profile.
- **Immediate AI support:** DeepSeek provides a short, warm, non-diagnostic response in Chinese or English.
- **Two-layer review:** AI performs an initial classification and moderation pass; a human administrator makes the final publication decision.
- **Consent-based publication:** A post appears on the public wall only when it is approved and the author agreed to anonymous public sharing.
- **Semantic moderation:** Text is normalized before analysis to help handle full-width characters, zero-width characters, decorative combining marks, homophones, and other attempts to bypass literal keyword checks.
- **Care reactions:** Visitors can respond with supportive reactions such as "I hear you", "A gentle hug", "Me too", and "I'm concerned".
- **Crisis escalation:** A high AI intensity, a crisis moderation result, or at least three "I'm concerned" reactions moves a post into the priority safety queue and removes it from the public wall.
- **Macao help resources:** Crisis notices include the project-provided Macao Caritas Life Hope Hotline number, 28525222, together with encouragement to contact a trusted adult or school social worker. Resource details should be independently verified before production use.
- **Bilingual interface:** Static interface text, navigation, forms, notices, charts, and AI-generated supportive responses support Chinese and English.
- **Community insights dashboard:** Password-protected administrators can view anonymous aggregates such as post counts, category and intensity distributions, daily posting trends, and reaction totals.
- **Public context display:** The welcome area separates external research and media context from data generated by the platform.
- **Warm visual design:** The Streamlit interface uses a soft, calm palette and responsive cards without a separate frontend framework.

## How Moderation and Safety Work

```text
User writes a post or reply
        |
        v
Text normalization
(NFKC, zero-width/decoration cleanup, pinyin fallback)
        |
        v
One DeepSeek JSON analysis
(category + intensity + supportive reply + moderation)
        |
        +--> crisis or intensity >= 4
        |        |
        |        v
        |   Crisis queue + help resources
        |
        +--> safe or need_review
                 |
                 v
             Pending queue
                 |
                 v
          Human administrator review
             /              \
            v                v
       Approved            Rejected
          |
          v
Public wall only when consent_public = 1
```

Additional escalation checks run when care reactions are written:

```text
worried reactions >= 3 OR intensity >= 4
        |
        v
post status = crisis
        |
        v
priority admin queue + help resources + no public display
```

All new posts remain pending unless they are escalated to `crisis`. Replies also remain pending until a human administrator approves them. The existing SQLite layer keeps these transitions transactional.

## Tech Stack

- **Python**
- **Streamlit**
- **SQLite**
- **DeepSeek LLM** through its OpenAI-compatible API and the Python `openai` SDK
- **pypinyin** for the local pinyin fallback check

The application intentionally does not use React, Flask, Django, or a separate frontend framework.

## Responsible AI and Limitations

- The AI response is supportive language, not a diagnosis, assessment, or treatment recommendation.
- AI moderation is imperfect. Human review remains the final publication gate.
- Crisis detection is designed to fail closed toward `need_review` when the model response is invalid or unavailable.
- The prototype uses explicitly marked fictional demo data. It is not designed to collect real personal information.
- The local SQLite database is plain storage. Do not place real personal data or the database file in the public repository.
- Reaction totals count writes/clicks, not unique people.
- The system has no real-time human monitoring, alert dispatch, account system, anti-abuse rate limiting, or guaranteed response time.
- The current crisis dashboard count represents posts whose current database status is `crisis`; the schema does not preserve a separate history of every escalation event.
- The project-provided hotline and resource wording should be checked with an appropriate local authority before any real-world deployment.

## Local Setup

### 1. Create a virtual environment

macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

Run from the repository root:

```bash
python -m pip install -r outputs/requirements.txt
```

### 3. Configure secrets

The current source reads credentials from environment variables:

macOS or Linux:

```bash
export DEEPSEEK_API_KEY="your-deepseek-api-key"
export ADMIN_PASS="choose-a-long-admin-password"
```

Windows PowerShell:

```powershell
$env:DEEPSEEK_API_KEY="your-deepseek-api-key"
$env:ADMIN_PASS="choose-a-long-admin-password"
```

For hosted deployments, use the platform's secret store or Streamlit Secrets management rather than committing credentials. The current application lookup is environment-variable based, so the deployment configuration must expose these values to the process. Never hard-code an API key or administrator password.

### 4. Optional: load fictional demo data

```bash
python outputs/seed.py
```

The seed script creates seven clearly marked fictional posts and sample replies without calling the DeepSeek API. It is intended for demos only.

### 5. Start the app

```bash
python -m streamlit run outputs/app.py
```

The browser address printed by Streamlit is the local preview URL. The application creates `outputs/heart_wall.db` when needed; database files are ignored by Git.

## Repository Layout

```text
.
|-- README.md
|-- .gitignore
|-- outputs/
|   |-- app.py              # Streamlit UI and page flow
|   |-- ai.py               # DeepSeek request, validation, and fallbacks
|   |-- db.py               # SQLite schema, writes, review, reactions, escalation
|   |-- seed.py             # Fictional demo data
|   |-- requirements.txt
|   `-- documentation files
|-- tests/
|   `-- test_*.py
`-- work/
    `-- local development helpers
```

The application entrypoint is `outputs/app.py`. The repository keeps automated tests in `tests/`; the remaining files under `work/` are local development helpers and are not required to run the deployed application.

## Running Tests

The test suite uses temporary SQLite databases and mocked HTTP responses. It does not need a real DeepSeek key and does not spend API credits.

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

For a lightweight type check, use the local `ty` installation if available:

```bash
work/typecheck_tools/bin/ty check --python .venv outputs/app.py
```

## Deployment

The deployed Streamlit app uses `outputs/app.py` as its entrypoint. Configure `DEEPSEEK_API_KEY` and `ADMIN_PASS` through the deployment platform's secret settings, then redeploy after code changes.
